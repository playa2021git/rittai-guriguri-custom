# GitHubだけで設定を共有する場合の速度測定

測定日：2026年11月7日（日本時間）。試験専用ファイルのみ更新し、本番の先生用許可設定と生徒用教材の処理は変更していません。

| 試行 | GitHub Pages経由 | GitHub直接取得・更新確認付き | GitHub直接取得・通常URL |
| --- | ---: | ---: | ---: |
| 1 | 46.34秒 | 120秒以内に確認できず | 120秒以内に確認できず |
| 2 | 45.61秒 | 120秒以内に確認できず | 120秒以内に確認できず |
| 3 | 46.14秒 | 60.16秒 | 60.16秒 |

GitHub Pages経由の中央値は46.14秒でした。先生の実行ボタンに相当するワークフロー実行要求の直前から、認証なしの読み取りで設定IDの変更を確認できるまでを測りました。実行環境の起動待ち・ファイル保存・公開処理・通信・2秒ごとの確認間隔を含みます。GitHub Actions実行環境は標準の `ubuntu-latest` です。

直接取得の応答には `Cache-Control: max-age=300` がありました。URLに確認用クエリを付けた方法でも遅延が残り、別途 `Cache-Control: no-cache, no-store` を送った読み取りでも古い内容が返ることを確認しました。今回の結果では、GitHubだけの構成で常に5秒程度の更新を期待することはできません。

現在のChatGPT Sites版は5秒ごとの設定確認です。今回の比較ではSitesの設定を書き換えておらず、5秒という値は現在のアプリの確認間隔です。生徒の端末には別途通信時間が加わります。

少数回の測定で、学校のChromebookや学校回線での結果ではありません。手動で試す場合は `/teacher-benchmark/` を開き、測定開始後にGitHubの「Run workflow」を実行してください。手動測定には画面での操作時間も含まれます。

生データと実行URLは [results.json](results.json) に保存しています。試行1の一時的な404は、この試験ページの初回公開待ちに発生し、その後46.34秒で正常な更新を確認しています。
